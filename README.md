# Практическая работа №1. Знакомство с проектом: C#, .NET и Git

## Цель работы
Установить и проверить окружение для разработки на C# (.NET SDK, VS Code, Git), изучить базовый синтаксис языка (переменные, константы, арифметика, интерполяция строк) и освоить рабочий цикл Git.

## ПР1. Ответы на контрольные вопросы

### 1. Чем компилируемый язык (C#) отличается от интерпретируемого (Python) с точки зрения того, когда обнаруживаются ошибки?
В компилируемом C# все синтаксические ошибки обнаруживаются еще до запуска программы — на этапе сборки проекта (build). Компилятор просто откажется собирать код, если где-то пропущена точка с запятой или не совпадает тип данных. В интерпретируемом Python ошибки обнаруживаются прямо во время выполнения (runtime) при построчном чтении кода. То есть программа на Python может успешно работать до тех пор, пока выполнение не дойдет до конкретной строки с ошибкой.

### 2. Что делает команда dotnet run на самом деле — из каких двух шагов она состоит?
Команда dotnet run последовательно выполняет два основных шага:
1. **Сборка проекта (build)** — компилятор проверяет код на ошибки и переводит исходные .cs файлы в промежуточный машинно-независимый IL-байткод.
2. **Запуск** — среда выполнения .NET разворачивает полученную сборку и запускает готовую программу.

### 3. Зачем нужны папки bin/ и obj/ и почему их не нужно хранить в Git?
В папке `obj/` лежат временные служебные файлы, которые нужны компилятору в процессе сборки. В папку `bin/` компилятор складывает финальный результат — готовые исполняемые файлы программы (.exe и .dll). Их не нужно хранить в Git, потому что это не исходный код, а результат компиляции под конкретный компьютер. Они весят много и легко пересоздаются заново одной командой dotnet run на любой машине. Для их скрытия используется файл .gitignore.

### 4. В чём разница между git commit и git push?
- **git commit** — делает локальный «снимок» (фиксирует изменения) текущего состояния файлов внутри твоего компьютера. На удаленный сервер файлы при этом не отправляются.
- **git push** — берет все твои локальные сделанные коммиты и заливает их копию в облачный репозиторий на GitHub, чтобы их увидел преподаватель.

### 5. Чем отличаются конкатенация строк через + и интерполяция через $"..."? Какой способ предпочтительнее и почему?
Конкатенация — это механическое склеивание строк и переменных с помощью знака плюс (`"А" + " " + "Б"`). Интерполяция (`$" {var} "`) позволяет записывать переменные прямо внутри текста в фигурных скобках. Интерполяция намного предпочтительнее, потому что код получается компактным, читаемым, в нем гораздо сложнее запутаться в пробелах и кавычках при выводе больших строк.

### 6. Что произойдёт, если разделить int на int, если результат должен быть дробным? Как это исправить?
Произойдет целочисленное деление, при котором C# просто отбросит всю дробную часть результата без всякого округления (например, 25 / 4 даст ровно 6). Чтобы это исправить и получить точный дробный результат, нужно применить явное приведение типов — написать перед одним из операндов ключевое слово `(double)`, чтобы заставить C# считать выражение в дробном формате.

### 7. Чем const отличается от обычной переменной? Приведите свой пример, когда стоит использовать const.
Значение обычной переменной можно перезаписывать и менять сколько угодно раз во время работы программы. Значение константы (`const`) жестко фиксируется один раз при создании, и компилятор запрещает его изменять. Константы стоит использовать для величин, которые железно неизменны на протяжении всей работы софта — например, ставка НДС (`const double VatRate = 0.20`) или количество месяцев в семестре.

### 8. Что такое top-level statements и чем они отличаются от классического class Program { static void Main() }?
Top-level statements — это современный синтаксис (начиная с C# 9), который позволяет писать логику программы сразу в файле `Program.cs` с первой строчки, без создания обязательной обёртки в виде класса `Program` и метода `Main()`. Под капотом компилятор сам автоматически достраивает всю классическую структуру, но код для разработчика становится чище, короче и избавляет от лишних фигурных скобок в простых консольных утилитах.
